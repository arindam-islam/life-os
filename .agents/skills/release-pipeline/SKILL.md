---name: release-pipelinedescription: Permanent Life OS Release Process guidelines and state machine CLI operations for the 6-stage lifecycle (Dev -> Test -> Security -> Staging -> QA -> Production).---# Life OS Release Pipeline & State Machine SkillThis skill enforces the permanent fail-closed release state machine across all engineering and deployment tracks.## Release Lifecycle Stages```textDev → Test → Security → Staging → QA → Production```### Stage Rules & Responsible Roles1. **Dev (`Engineering Agent`)**:   - Initializes release candidate tied to an exact 40-character Git commit SHA.   - Command: `python3 scripts/release_state_machine.py init --sha <COMMIT_SHA> --track <TRACK_NAME>`2. **Test (`QA / Verification Agent` / `Engineering Agent`)**:   - Pre-requisite: `Dev` must be `PASSED`.   - Executes local automated unit and integration tests.   - Command: `python3 scripts/release_state_machine.py advance --release-id <REL_ID> --gate test --status PASSED --role "QA / Verification Agent" --evidence '{"tests": "PASSED"}'`3. **Security (`Security & Reliability Reviewer`)**:   - Pre-requisite: `Test` must be `PASSED`.   - Audits secret handling, SAIF compliance, telemetry boundary, and network exposure.   - Command: `python3 scripts/release_state_machine.py advance --release-id <REL_ID> --gate security --status PASSED --role "Security & Reliability Reviewer" --evidence '{"secrets": "CLEAN"}'`4. **Staging (`CTO / Architecture Agent`)**:   - Pre-requisite: `Security` must be `PASSED`.   - **Fail-Closed Rule**: Must use an isolated environment and synthetic/sanitized data. If no isolated staging environment exists, mark status as `BLOCKED`. Never rename local testing as staging.   - Command (if unblocked): `python3 scripts/release_state_machine.py advance --release-id <REL_ID> --gate staging --status PASSED --role "CTO / Architecture Agent" --staging-env-verified`5. **QA (`QA / Verification Agent`)**:   - Pre-requisite: `Staging` must be `PASSED`.   - Verifies exact QA-approved commit SHA against acceptance criteria.   - Command: `python3 scripts/release_state_machine.py advance --release-id <REL_ID> --gate qa --status PASSED --role "QA / Verification Agent"`6. **Production (`Orchestrator / Chief of Staff`)**:   - Pre-requisite: `QA` must be `PASSED`.   - Enforces exact commit SHA match and verified executable rollback plan before deployment.   - Command: `python3 scripts/release_state_machine.py advance --release-id <REL_ID> --gate production --status PASSED --role "Orchestrator / Chief of Staff"`## Core Policy Invariants- **Fail-Closed**: Any skipped gate, commit mismatch, missing evidence, or unverified rollback plan rejects release promotion.- **No Gate Skipping**: Gates must pass strictly in order.- **Founder Approval Boundary**: Product owner approves outcomes and material risk decisions only—not code, tests, or engineering details.- **Ledger Verification**: Validate ledger state at any time via `python3 scripts/release_state_machine.py validate`.
